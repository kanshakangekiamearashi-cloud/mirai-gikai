# Vercel公開手順（みらい議会＠東広島市フォーク）

作成日: 2026-11-25
対象リポジトリ: kanshakangekiamearashi-cloud/mirai-gikai（develop ブランチ）
前提: このドキュメントは、ソースコード（`web/src/lib/env.ts`、`admin/src/lib/env.ts`、`packages/supabase/src/admin.ts`、各 API ルート）を実際に調査し、`.env.example` と照合した結果に基づく。

## 0. このリポジトリ側で済ませたこと（2026-11-25 のコミット）

- `web/vercel.json` / `admin/vercel.json` から、main／develop への push で自動デプロイを無効化する `git.deploymentEnabled` 設定を削除した。これで Vercel の通常の Git 連携デプロイが使える（Deploy Hook 方式は使わない）。
  - `ignoreCommand`（`scripts/vercel-ignore-build.mjs`）は残してある。main／develop は常時ビルドされ、それ以外のブランチは open な PR がある時だけ Preview がビルドされる。
- ルート `.env.example` に、コードで使われているのに載っていなかった任意変数（`NEXT_PUBLIC_GA_TRACKING_ID`、`ARTICLE_REPORT_SLACK_WEBHOOK_URL`、`LANGFUSE_PROMPT_LABEL`、`OPEN_DATA_RATE_LIMIT_PER_IP/GLOBAL`、admin の `GCP_*`）を追加し、必須／推奨／任意の区別を明記した。
- `web/.env.example` を実態に合わせて修正した（コードで未使用だった `NEXT_PUBLIC_ADMIN_URL` を廃止し、実際に使う `ADMIN_URL`・`SUPABASE_URL`・`SUPABASE_SECRET_KEY`・`REVALIDATE_SECRET` を記載。ポートも admin の実値 3001 に統一）。

## 1. 環境変数の要否（調査結果）

### web（公開サイト）

| 変数 | 要否 | 未設定だと |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 必須 | `web/src/lib/env.ts` が起動時にエラーを投げ、全ページが落ちる |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 必須 | 同上 |
| `SUPABASE_URL` | 必須（閲覧データ取得） | サーバー側のデータ取得（`createAdminClient`）が失敗する |
| `SUPABASE_SECRET_KEY` | 必須（閲覧データ取得） | 同上。サーバー側専用。`NEXT_PUBLIC_` には絶対に入れない |
| `REVALIDATE_SECRET` | 推奨 | `/api/revalidate` が 500 を返して安全側に倒れる（公開自体は可能）。web と admin で同じ値にする |
| `AI_GATEWAY_API_KEY` | AI機能を使うなら必須 | 閲覧系は動作する。AIチャット／インタビューだけエラーになる |
| `ADMIN_URL` | 推奨 | admin へのリンク等が localhost 向きになる |
| `BASIC_AUTH_USER` / `BASIC_AUTH_PASSWORD` | 任意 | 未設定（または片方だけ）だと Basic 認証は無効＝無認証で公開される。公開前の下見期間だけ設定する用途 |
| `CHAT_DAILY_USER_COST_LIMIT_USD` 等3つ | 任意 | デフォルト 0.5 / 50 / 1000 USD で動作する |
| `LANGFUSE_*`、`NEXT_PUBLIC_GA_TRACKING_ID`、`ARTICLE_REPORT_SLACK_WEBHOOK_URL`、`OPEN_DATA_RATE_LIMIT_*` | 任意 | 各機能が無効になるだけで動作する |

### admin（管理画面）

| 変数 | 要否 | 備考 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | 必須 | web と同じ値。未設定だと `admin/src/lib/env.ts` が起動時にエラー |
| `SUPABASE_URL` / `SUPABASE_SECRET_KEY` | 必須 | サーバー側処理用 |
| `REVALIDATE_SECRET` | 推奨 | web と同じ値 |
| `NEXT_PUBLIC_WEB_URL` | 推奨 | web の公開URL |
| `ADMIN_MCP_TOKEN` | MCPを使うなら必須 | 自分で作ったランダム文字列。推測できない長さにする |
| `GCP_PROJECT_ID` / `GCP_REGION` / `GCP_TOPIC_ANALYSIS_JOB` / `GCP_SA_KEY` | 任意 | トピック分析を Cloud Run で実行する場合のみ |

### Supabase 接続に必要な情報（どこで手に入るか）

Supabase のプロジェクト画面 → Settings → API Keys で、次の4つを控える。

1. Project URL（`https://<プロジェクトref>.supabase.co`）→ `SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_URL` の両方に入れる
2. Publishable key → `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`（公開してよい鍵）
3. Secret key → `SUPABASE_SECRET_KEY`（**絶対に公開しない**。GitHub にも書かない。Vercel の環境変数欄にだけ入れる）
4. プロジェクト作成時に自分で決めた Database Password（マイグレーション実行時に使う）

## 2. あなたの操作手順（スマートフォンのブラウザでできます）

### 手順A：Supabase のプロジェクトを作る

1. supabase.com を開き、GitHub アカウントでログインする
2. 「New Project」を押し、名前（例：mirai-gikai-higashihiroshima）、Database Password（自分で決めて必ずメモ）、リージョン Tokyo（Northeast Asia）を選んで作成する
3. 作成が終わるまで数分待つ
4. Settings → API Keys を開き、上記1〜3の値をメモする
5. データベースのテーブル作成（マイグレーション119件）は、PCがある場合は README の手順（`supabase link` → `supabase db push --include-all --yes` → `supabase config push --yes`）で行う。PCがない場合は、この手順書の「残作業」参照

### 手順B：Vercel に web を公開する

1. vercel.com を開き、GitHub アカウントでログインする
2. 「Add New → Project」を押し、このフォーク（mirai-gikai）を選んで Import する
3. 設定で **Root Directory を `web`** に変更する（Framework は Next.js のまま、Build Command 等は既定のまま）
4. 「Environment Variables」の欄に、手順Aでメモした値で次を入れる：
   - `NEXT_PUBLIC_SUPABASE_URL` ＝ Project URL
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` ＝ Publishable key
   - `SUPABASE_URL` ＝ Project URL
   - `SUPABASE_SECRET_KEY` ＝ Secret key
   - `REVALIDATE_SECRET` ＝ 自分で作った長いランダム文字列（メモしておく）
5. 「Deploy」を押す。終わると `https://<プロジェクト名>.vercel.app` の公開URLが発行される
6. そのURLをスマホで開き、トップページが表示されるか確認する（データ未投入の間は議案一覧が空なのが正常）

### 手順C：admin が必要になったら

手順Bと同じ要領で、もう1つプロジェクトを作り、Root Directory を `admin` にする。環境変数は admin の表のとおり（`NEXT_PUBLIC_WEB_URL` には手順Bの公開URLを入れる）。その後、web 側の `ADMIN_URL` に admin のURLを設定して web を再デプロイする。admin のログインには Supabase Auth の Google OAuth 設定（Google Cloud での OAuth クライアント作成と、Supabase 側のリダイレクトURL登録）が別途必要。

## 3. セキュリティ確認結果（2026-11-25 調査）

- `.env` 本体は `.gitignore` で除外され、GitHub に追跡されているのは `.env.example`（空値）だけであることを確認した
- 秘密鍵（`SUPABASE_SECRET_KEY`）を使う `createAdminClient` はサーバー側（`server/` 配下のリポジトリ層）からのみ呼ばれ、Client Component から参照されていないことを確認した
- `/api/revalidate` は `REVALIDATE_SECRET` 未設定時に 500、値が違う時に 401 を返す（安全側）
- seed の固定パスワード管理者（admin@example.com）は、接続先が localhost の時だけ作成されるガードがあり、本番 Supabase には作られない
- RLS は全テーブルで有効化されポリシーは定義しない（デフォルト全拒否）設計で、データアクセスは Secret Key 経由に一本化されている
- 注意点：Basic 認証は未設定だと無効になる。「一般公開＝無認証が正解」だが、下見期間に鍵をかけたい場合は `BASIC_AUTH_USER` と `BASIC_AUTH_PASSWORD` の両方を設定すること
- 注意点：AI機能を有効にする場合は、コスト上限（`CHAT_*_COST_LIMIT_USD`）のデフォルト値が意図に合うか確認すること

## 4. 残作業（このコミットでは完了していないこと）

1. **ビルドの実地検証**：このリポジトリのローカルコピーに対する安全チェックの都合で、`pnpm install` ／ `pnpm build` をこちらで実行できていない。最初の Vercel デプロイが実質の初回ビルド検証になる。ビルドエラーが出たら、Vercel の Deployment ログの全文を共有してもらえれば原因を特定して直す
2. **マイグレーションの適用**：Supabase クラウドへの `supabase db push` はアカウント持ち主の認証が要るため、あなたの操作（手順A-5）が必要
3. **東広島市データの DB 投入**：議案・一般質問・議員データは `packages/seed/higashihiroshima/` の独立ファイルのままで、DB スキーマに市議会用のテーブルがない。Vercel 公開後も中身が表示されるようにするには、別途データ投入の開発が必要（公開の前提条件ではないが、公開の目的を果たすには必須）
4. **バイナリ画像**：ヒーロー画像・OGP・favicon は本家のまま。公開運用の前に PC から差し替えること
